# Надёжность и системная полировка

## Локальная диагностика

Gym пишет только локальный лог `logs/gym.log` в каталоге данных приложения. Размер
активного файла ограничен 512 КиБ, сохраняются три предыдущие ротации. Путь к логу
показывается в разделе «О приложении» и на fatal-экране.

## SQLite

- Один `Mutex<Connection>` последовательно выполняет команды внутри процесса.
- Транзакции защищают изменение порядка упражнений и сохранение тренировки.
- Повторное и конкурентное завершение одного reminder не создаёт дубликаты.
- Ограничение и конкурентный тест гарантируют не более одного pending reminder.
- `busy_timeout` пережидает краткую внешнюю блокировку; ошибка остаётся
  структурированной, записывается в лог, после снятия блокировки команды снова работают.
- Ошибка открытия каталога, миграции или базы не запускает scheduler и tray. Вместо
  аварийного завершения показывается fatal-экран.

## Offline и permissions

Production-код не содержит HTTP-клиентов. `npm run check:offline` проверяет frontend,
Rust-код и прямые зависимости. URL dev-сервера используется только командой разработки.

Webview разрешены только подписка и отписка от событий, а notification plugin получает
собственный стандартный набор разрешений. Для production включён Content Security Policy.

## Интерфейс

- Главное окно по умолчанию 1100 × 760, минимум 680 × 520.
- Reminder остаётся компактным и прокручивает длинный список упражнений.
- Layout адаптируется к узким окнам и системному scaling.
- Есть skip-link, видимый keyboard focus, live-регионы ошибок и поддержка reduced motion.
- На macOS tray использует template icon и автоматически меняется для светлой/тёмной
  строки меню; Linux использует цветную иконку приложения.

## Проверка перед выпуском

Автотесты покрывают ротацию, конкурентные вызовы, идемпотентность и временную блокировку
SQLite. Отдельно на реальных macOS и Linux проверяются 100%, 125%, 150% scaling,
клавиатурная навигация, VoiceOver/Orca, светлая/тёмная тема и системные уведомления.
